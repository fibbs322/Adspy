# AdSpy — гайд по запуску, деплою и домену

Это твой собственный сервис-трекер рекламы Facebook: поиск по бренду/странице,
дата запуска креатива, сколько дней он уже крутится, сохранённые поиски и избранное.
Работает через официальный **Meta Ad Library API** — легально и бесплатно.

Структура проекта:
```
adspy/
  backend/     — Node.js/Express API + SQLite база
  frontend/    — статический сайт (HTML/CSS/JS), отдаётся тем же сервером
  DEPLOY_GUIDE.md — этот файл
```

---

## Шаг 1. Получить доступ к Facebook Ad Library API

Без этого шага сайт будет работать (регистрация, логин, интерфейс), но поиск
объявлений будет возвращать ошибку "FB_ACCESS_TOKEN не настроен".

1. Зайди на https://developers.facebook.com/ и создай аккаунт разработчика (нужен обычный личный аккаунт Facebook).
2. Пройди верификацию личности (ID verification) — Meta требует её именно для доступа
   к Ad Library API, чтобы бороться со спамом и слежкой. Это делается в настройках
   разработчика: https://developers.facebook.com/docs/marketing-api/access — раздел "Identity confirmation".
   Обычно нужно загрузить фото документа и подтвердить номер телефона/адрес.
3. Создай приложение (App) в https://developers.facebook.com/apps/ — тип "Business" подойдёт.
4. В приложении получи **User Access Token** (или System User Token для долгоживущего доступа)
   с правом на чтение Ad Library (специального "scope" для этого API не требуется,
   достаточно обычного валидного токена верифицированного аккаунта).
5. Проверь токен вручную в браузере:
   ```
   https://graph.facebook.com/v21.0/ads_archive?access_token=ТВОЙ_ТОКЕН&search_terms=nike&ad_type=ALL&ad_reached_countries=["US"]
   ```
   Если видишь JSON со списком объявлений — всё работает.

Официальная документация: https://www.facebook.com/ads/library/api/

**Важно:** токены пользователя Facebook часто короткоживущие (1-2 часа) или
долгоживущие (60 дней). Для стабильной работы сервиса изучи получение
System User Token через Business Manager — он не истекает так быстро.
Когда токен протухнет, поиск начнёт возвращать ошибку от Facebook — тогда
просто обнови значение `FB_ACCESS_TOKEN` на хостинге и перезапусти сервис.

## Шаг 2. Запуск локально (проверить, что всё работает)

Нужен установленный Node.js (версия 18+): https://nodejs.org

```bash
cd adspy/backend
cp .env.example .env
```

Открой `.env` и заполни:
- `FB_ACCESS_TOKEN` — токен из шага 1
- `JWT_SECRET` — любая длинная случайная строка (можно сгенерировать: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`)

Дальше:
```bash
npm install
npm start
```

Открой http://localhost:3000 — должна открыться страница входа. Зарегистрируй
аккаунт и попробуй найти рекламу, например, по слову "nike".

## Шаг 3. Бесплатный деплой (чтобы сайтом могли пользоваться другие)

Самый простой бесплатный вариант — **Render.com** (есть бесплатный план Web Service).
Альтернативы с похожим бесплатным тарифом: Railway.app, Fly.io, Cyclic.sh.

### Вариант A: Render.com

1. Залей проект на GitHub (создай репозиторий, например `adspy`, и запушь папку `adspy/`).
   Если не умеешь работать с git — просто попроси меня (Claude) сделать это за тебя,
   когда дашь доступ к своему GitHub.
2. Зайди на https://render.com, зарегистрируйся (можно через GitHub).
3. "New" → "Web Service" → выбери свой репозиторий.
4. Настройки:
   - **Root Directory:** `backend`
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free
5. В разделе "Environment" добавь переменные окружения:
   - `FB_ACCESS_TOKEN` = твой токен
   - `JWT_SECRET` = твоя случайная строка
   - `CORS_ORIGIN` = `*` (или твой будущий домен, когда определишься)
6. Нажми "Create Web Service". Через пару минут Render даст тебе адрес вида
   `https://adspy-xxxx.onrender.com` — сайт уже доступен всем в интернете.

**Важный нюанс бесплатного плана Render:** диск не постоянный — файл SQLite
(`db/adspy.db`) может очиститься при перезапуске контейнера (это бывает на
бесплатном тарифе после периода неактивности). Для хобби-проекта это
нормально, но если нужна надёжность — на Render есть платный "Persistent Disk"
($) или замена SQLite на бесплатную PostgreSQL (Render даёт бесплатную
Postgres-базу на 90 дней, потом тоже платно — я могу помочь переписать под неё,
если понадобится).

### Вариант B: Railway.app
Похожий процесс: "New Project" → "Deploy from GitHub repo" → указать `backend` как
корень, задать те же переменные окружения. У Railway бесплатный план ограничен
по часам использования в месяц.

## Шаг 4. Домен

1. Купи домен у любого регистратора: Namecheap, Porkbun, GoDaddy, reg.ru, или
   украинский Imena.ua / ukraine.com.ua. Обычно $8–15/год за `.com`, дешевле за `.site`/`.online`.
2. В настройках твоего хостинга (Render/Railway) есть раздел "Custom Domain" —
   там дадут CNAME-запись (например, `adspy-xxxx.onrender.com`).
3. Зайди в панель управления DNS у регистратора домена и добавь запись:
   - Тип: `CNAME`
   - Имя: `www` (или `@` для корневого домена, если регистратор поддерживает ALIAS/ANAME)
   - Значение: адрес, который дал хостинг
4. Подожди 10 минут – 24 часа на распространение DNS. Render/Railway сами
   выпустят бесплатный SSL-сертификат (HTTPS) для твоего домена.
5. Обнови переменную `CORS_ORIGIN` на хостинге на свой домен, например
   `https://adspy.com`, и перезапусти сервис — это защитит API от использования
   с чужих сайтов.

## Вход через Google

На сайте есть кнопка «Continue with Google» — пользователи могут входить одним
кликом через свой Gmail-аккаунт, без пароля. Чтобы включить её:

1. Зайди на https://console.cloud.google.com/ (с любым Google-аккаунтом) и создай проект
   (если ещё нет) — кнопка в верхней панели рядом с логотипом Google Cloud.
2. Перейди в **APIs & Services** → **OAuth consent screen**.
   - User Type: **External**.
   - Заполни название приложения (например, «AdSpy»), свою почту для поддержки — остальное можно пропустить.
   - Сохрани. Пока приложение в статусе "Testing" — это нормально, можно
     добавить себя и других тестировщиков в разделе "Test users", либо
     опубликовать приложение (Publish App), чтобы вход был доступен всем.
3. Перейди в **APIs & Services** → **Credentials** → **Create Credentials** → **OAuth client ID**.
   - Application type: **Web application**.
   - **Authorized JavaScript origins** — добавь адрес своего сайта, например:
     `https://adspy-xxxx.onrender.com` (и свой домен, если уже подключил).
   - Authorized redirect URIs можно оставить пустым — они не нужны для этого способа входа.
   - Нажми **Create** — появится **Client ID** (строка вида `123456-abc.apps.googleusercontent.com`).
4. Скопируй этот Client ID и добавь его как переменную окружения `GOOGLE_CLIENT_ID`
   на хостинге (Render → твой сервис → Environment → Add Environment Variable).
5. Сохрани — Render сам передеплоит сервис. После этого на сайте появится кнопка Google.

**Важно:** при каждом новом домене (например, когда подключишь свой домен вместо
`onrender.com`) нужно будет зайти в Google Cloud Console → Credentials → твой
OAuth client → и добавить новый адрес в **Authorized JavaScript origins**,
иначе кнопка Google перестанет работать на новом домене.

## Подтверждение email при регистрации

При регистрации по email/паролю сайт отправляет на почту 6-значный код, который
нужно ввести, чтобы активировать аккаунт (вход через Google подтверждения не требует —
Google и так подтвердил почту). Для отправки писем используется бесплатный сервис **Brevo**
(не требует своего домена — достаточно подтвердить один email-отправитель).

1. Зайди на https://www.brevo.com и зарегистрируйся бесплатно.
2. В настройках (Settings → Senders, Domains & Dedicated IPs → Senders) добавь свой email
   как отправителя и подтверди его — Brevo пришлёт письмо со ссылкой подтверждения.
3. Перейди в Settings → SMTP & API → API Keys, создай новый API-ключ.
4. Добавь на хостинге (Render → твой сервис → Environment) три переменные:
   - `BREVO_API_KEY` = твой API-ключ
   - `MAIL_FROM_EMAIL` = тот email, который ты подтвердил как отправителя
   - `MAIL_FROM_NAME` = `AdSpy` (или любое имя отправителя)
5. Сохрани — после передеплоя регистрация начнёт присылать код подтверждения.

**Важно:** пока эти переменные не заданы, регистрация работает как раньше — без
подтверждения почты, чтобы ничего не сломалось. Бесплатный план Brevo даёт 300 писем
в день — для старта более чем достаточно.

## Многопользовательский доступ

Сайт уже поддерживает регистрацию и вход нескольких пользователей — у каждого
свои сохранённые поиски и избранное (таблицы `users`, `saved_searches`,
`favorites` в SQLite). Ничего дополнительно настраивать не нужно — просто дай
ссылку на сайт тем, кому нужно, и они зарегистрируются сами.

Если захочешь:
- **Ограничить доступ** только избранным людям — могу добавить инвайт-коды для регистрации.
- **Админку** — чтобы ты видел всех пользователей и мог их удалять.
- **Общие (командные) сохранённые поиски** — чтобы вся команда видела одни и те же отслеживаемые бренды.

Просто скажи, что из этого нужно, и я добавлю.

## Ограничения, о которых стоит знать

- Facebook/Meta **не отдаёт точный бюджет или число показов** обычной
  коммерческой рекламы через публичный API (это раскрывается только для
  политической/социальной рекламы). Сервис оценивает "объём" косвенно —
  через число дней показа и количество разных креативов у одной страницы.
  Платные сервисы вроде AdSpy/PiPiAds делают то же самое, просто с более
  красивой подачей.
- Бесплатные тарифы хостингов имеют лимиты (сон при неактивности, ограничение
  часов, временное хранилище). Для серьёзной нагрузки в будущем придётся
  перейти на платный тариф ($5–7/мес обычно достаточно).
- Соблюдай условия использования Meta Ad Library API — не превышай лимиты
  запросов и не используй данные для целей, запрещённых их политикой
  (например, точечная слежка за конкретными людьми; API и так показывает
  только объявления, а не личные данные пользователей).
